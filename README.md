# カートリッジ棚 — 設置手順

`.nes / .fds / .smc / .sfc / .gba / .nds` を iPad のブラウザで動かすためのフロントエンドです。
エミュレーション本体は EmulatorJS（RetroArch の WebAssembly コア）を使います。

## 1. 置く

GitHub の Web UI で新しいリポジトリを作り、次の 2 ファイルをアップロードします。

```
index.html
sw.js
```

Settings → Pages で `main` ブランチを公開。**https でないとオフライン機能（Service Worker）が動かない**ので、GitHub Pages の URL をそのまま使ってください。

## 2. iPad に入れる

Safari で Pages の URL を開く → 共有 → **ホーム画面に追加**。
全画面のアプリとして起動し、アドレスバーが消えます。

## 3. タッチ操作

ROM を起動すると、タッチ端末では十字キーとボタンが自動で出ます。**ゲーム画面には重ねず、画面の外側**に置くので、指で絵が隠れません。

- **縦持ち** … 画面の下に、左＝十字キー／右＝A・B・X・Y
- **横持ち** … 画面の左右に振り分け（左端＝十字キー、右端＝ボタン）
- どちらもスクロールなしで 1 画面に収まります
- 十字キーは斜め入力対応。ボタンは同時押し・指を滑らせての持ち替えができます
- 上部のバー … `‹ ROM選択` / `パッド`（表示切替）/ `全画面` / `メニュー`（速度・セーブ枠）
- ファミコンの ROM では X・Y・L・R が消え、A・B の 2 ボタンになります

常に出す／出さないは「設定 → タッチ操作パッド」で固定できます。

## 4. オフラインで使えるようにする

コアは機種ごとに約 2〜30 MB あり、**初回だけオンラインで取得**します。

1. オンライン状態で、動かしたい機種の ROM を 1 本ずつ起動する
2. 起動できたら、選択画面のラベルが「保存済み — オフライン可」に変わる
3. 以降その機種は機内モードでも動く

ラベルは localStorage のフラグだけでなく、**EmulatorJS 本体が実際に端末内に残っているか**を見て表示しています。ブラウザのサイトデータを消したあとなどは「本体の再取得が必要（オンラインで一度起動）」と出るので、その場合はもう一度オンラインで起動してください。

つまり NES / SFC / GBA / DS の 4 機種を使うなら、**最初に 4 本、オンラインで起動**しておけば準備完了です。

## 5. Google ドライブ読み込み（使う場合のみ）

Google Cloud Console で：

1. プロジェクトを作り、**Google Drive API** と **Google Picker API** を有効化
2. **API キー**を作成
3. **OAuth 2.0 クライアント ID**（種類：ウェブアプリケーション）を作成し、
   「承認済みの JavaScript 生成元」に GitHub Pages の URL を登録
4. アプリの「設定」にクライアント ID と API キーを貼る

入力値はその端末の localStorage にのみ保存されます。ドライブはオンライン時専用です。

## 仕様の対応状況

| 要件 | 状態 |
|---|---|
| .nes / .smc / .gba / .nds 起動 | 対応（.fds .sfc も） |
| ドライブから読み込み（オンライン時） | 対応（要 OAuth 設定） |
| 速度 1× / 2× / 4× / 8× | 対応。ただし後述 |
| セーブ / ロード即時 | 対応。ROM ごとに 4 枠、サムネイル付き |
| iPad タッチ操作 | 対応（画面外に配置する自前パッド。設定で常時表示／非表示に固定可） |
| オフライン使用 | 対応（初回オンライン起動が 1 機種 1 回必要） |

## 正直に伝えておくこと

- **8× は「目標値」です。** 実際の速度は端末の処理能力が上限になります。iPad で NES / SFC / GBA は 4〜8× まで出ますが、DS は等速維持すら重い機種があり、倍速はほぼ効きません。
- **速度とセーブ枠は EmulatorJS の内部 API を呼んでいます。** 公式が「将来変わりうる」と明言している部分なので、本体が更新されると動かなくなる可能性があります。その場合は画面が「歯車メニューを使ってください」と表示に切り替わり、EmulatorJS 標準の Fast Forward / Save State は引き続き使えます。壊れたら `EJS_CDN` の `stable` をバージョン固定（例 `4.2.3`）にするのが復旧手段です。
- **DS は melonDS を選ぶと BIOS が必須**です（bios7.bin / bios9.bin / firmware.bin）。BIOS 不要で動かすなら desmume2015 のまま使ってください。DS 下画面のタッチ入力はコアによって挙動が変わります。
- **単一ファイル構成にはできませんでした。** Service Worker は同一オリジンの独立したファイルでなければ登録できないため、`sw.js` が必須です。逆に、コアを CDN から取って端末内にキャッシュする方式にしたので、リポジトリに置くファイルは 2 つだけで済みます。
- ROM は同梱していません。手元の ROM を読み込んでください。
